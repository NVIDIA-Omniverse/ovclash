ovclash#

ovclash is a standalone clash-detection library for USD (Universal Scene Description) stages, usable outside Omniverse Kit, NVIDIA’s application framework. It ships as a Python wheel and as a C/C++ SDK archive. Both drive the same native runtime. It runs static, time-sampled dynamic, duplicate-search and point-vs-mesh queries. The Overview lists what it does and what ships. The source, the issue tracker and the release archives are on GitHub at NVIDIA-Omniverse/ovclash.

Scene access goes through ovstage, a separate runtime package that neither ovclash package bundles. The wheel declares the exact ovstage version, so pip installs it with ovclash. The SDK archive pins the same version in its requirements.txt; install it with pip before you build or run against the SDK archive. See Installing the ovstage runtime. When the configure step reports a missing or different ovstage, see Troubleshooting: the installed ovstage does not match the SDK archive; when an import or a run reports it, see ovstage dependency missing from the environment.

This documentation serves three audiences:

  • Python developers who install the wheel. Start with the Python Quickstart.

  • C/C++ developers who build against the SDK archive. Start with the C/C++ Quickstart.

  • Contributors who build, test and change ovclash in a source checkout. Start with Local Development and Contributing.

Note

  • Maturity: ovclash is pre-1.0 software. A breaking change can land in a minor or patch release. The Changelog calls out each one, and Maturity and versioning states the policy.

  • Backends: released packages use the ovstage backend. The OpenUSD build is an unpublished parity reference. See Backends.

  • Two API layers: the canonical ovclash API and the higher-level ovclash_suite API, the Suite API, ship in one native library. Each has a C ABI (C application binary interface) and a Python package. The Suite C ABI is built on the canonical one. The two Python packages are peers. A name that exists in both, such as RunSettings, means a different object in each. Members, values and defaults can differ. See Choosing an API Layer.

Table of Contents#

The pages under Get Started, Using ovclash, Persistence and Export, Tutorials, Guides, C/C++ Reference and Release Notes and Security are the consumer pages. They also ship as Markdown in the docs/consumer/ folder of the SDK archive, which carries all of them. The wheel ships no documentation pages. The API Reference is generated from the public headers and the Python docstrings and is available only as rendered HTML.

The pages under Building and Contributing, Developer Internals and Testing and KPIs are for contributors who work in an ovclash source checkout. They never ship as Markdown. The Testing and KPIs pages cover the KPI performance benchmark suite and the Sentinel correctness campaign.
