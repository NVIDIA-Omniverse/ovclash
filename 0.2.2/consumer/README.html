ovclash Python Package#

The ovclash wheel runs clash detection on USD stages from Python, outside Omniverse Kit. It installs three packages. All three bind the same native library through ctypes.

Package

Use it for

ovclash

The canonical API. It stays close to the C ABI: one runtime, one stage, one query at a time.

ovclash_suite

The Suite API: named queries, stored results, and HTML and JSON export.

omni.physxclashdetectioncore

The Suite API under the module names of the Kit extension, for code that you migrate from Kit.

Pick one package and stay in it. Same-named types in ovclash and ovclash_suite are not interchangeable; Choosing an API lists the differences.

This page is the Python guide. It ships as docs/consumer/README.md in the SDK archive and is the wheel’s description on the package index; the wheel ships no pages. overview.md introduces the whole package and lists every page. The C/C++ guide is the C quickstart.

Installation#

Requirements:

  • Python 3.10 or newer.

  • Windows x86_64, Linux x86_64 or Linux aarch64.

  • On Windows, the Microsoft Visual C++ Redistributable (x64). ovclash does not bundle the MSVC runtime, and its native library does not load without it.

  • On Linux, glibc 2.35 or newer and a libstdc++ that provides GLIBCXX_3.4.30; see Linux glibc baseline.

compatibility.md gives the platform tags and the version policy.

Install the wheel with pip:

python -m pip install ovclash

The wheel depends on one exact version of ovstage, the runtime that ovclash reads USD through. pip installs it together with ovclash. That version is published on public PyPI.

Check the installation:

python -m ovclash --version

The command prints the version of the loaded native library, as ovclash <version>. Without the pinned ovstage package, import ovclash raises OSError.

Optional extras#

The core API needs no extra. Install one with python -m pip install "ovclash[viewer]". When pip cannot resolve an extra’s packages, compare your environment with the version ranges that Python versions lists.

Extra

Adds

Use it for

viewer, viewer-ovstage

NumPy and warp-lang (Warp)

The zero-copy numpy() and warp() adapters of overlap-report buffers.

viewer-openusd

NumPy, warp-lang and usd-core

Code that imports Python OpenUSD (pxr) itself. usd-core comes from public PyPI.

Do not install usd-core to fix a failing query. ovstage supplies the USD runtime, and a second pxr in the process can shadow it. USD coexistence explains how the two can share a process.

Quick start#

The wheel ships a small stage, samples/data/time_sampled.usda, in the installed ovclash package directory. Its prims /Root/Xform_Primitives/Cube and /Root/Xform_Primitives/Plane overlap. python -m pip show ovclash prints the parent of that directory as Location, written <site-packages> on this page.

First query in Python#

from pathlib import Path

import ovclash
from ovclash import ClashRuntime, RunSettings

# The wheel ships this stage in samples/data/ of the package directory.
stage = Path(ovclash.__file__).parent / "samples" / "data" / "time_sampled.usda"

runtime = ClashRuntime()
try:
    runtime.open_stage(str(stage))
    runtime.set_run_settings(RunSettings(tolerance=0.0))
    runtime.set_scope(["/Root/Xform_Primitives/Cube"], ["/Root/Xform_Primitives/Plane"])
    runtime.run_pipeline()
    for index in range(runtime.get_overlap_count()):
        details = runtime.get_overlap_details(index)
        print(details.name0, details.name1, details.nb_elements)
finally:
    runtime.destroy()

Output:

/Root/Xform_Primitives/Cube /Root/Xform_Primitives/Plane 10

The ovclash_suite example runs the same query and saves its results. The samples/ directory of the package holds complete Python samples; samples.md describes them and their launchers.

Every other RunSettings field keeps its default. The command also accepts --multi-threaded from older command lines. It has no effect, and --help does not list it. --help and --version load the native library, but they do not open a stage.

Scope rules:

  • Without scope paths, the command queries the whole stage.

  • With set A only, the query tests the meshes of set A against each other.

  • With both sets, it tests set A against set B.

  • A scope path also covers the prim’s descendants.

Query rules:

  • A dynamic query (--dynamic with --end-time above --start-time) drops overlaps between two meshes whose transforms are not animated. Run a static query to find those overlaps.

  • --duplicates finds nothing in a dynamic query. Equal start and end times select a static query, which runs the duplicate search. On the bundled time_sampled.usda, --duplicates reports one pair, /Root/Xform_Primitives/Cube_Dup1 and /Root/Xform_Primitives/Cube_Dup2, with 12 triangles.

  • To query a range given in USD time codes, divide each time code by the stage’s time-codes-per-second rate. ClashRuntime.get_stage_timeline_data() reports that rate.

Output rules:

  • stdout holds only the JSON summary: one object, indented by two spaces, with sorted keys. You can redirect it to a file or pipe it straight into a JSON parser.

  • The version header, ovclash <version> - Standalone query CLI, and every diagnostic go to stderr. This includes the lines that native plugins write while the stage loads.

  • An overlap record holds the overlap’s first sampled frame only, so a dynamic query reports one frame per overlap.

ovclash#

ovclash is a thin binding of the canonical C ABI. One ClashRuntime owns the stage, the settings, the scope and the results. The first query shows the lifecycle:

  1. ClashRuntime() creates a native context.

  2. open_stage(path) opens a local USD file. Asset URIs are rejected.

  3. set_run_settings(RunSettings(...)) applies the settings. Unknown field names raise TypeError, and out-of-range values raise ValueError.

  4. set_scope(paths_a, paths_b) records the search sets. Call it after open_stage(), because a successful open drops the recorded scope.

  5. run_pipeline() runs every pipeline step on the calling thread.

  6. Read the results.

  7. destroy() releases the native context.

A failed native call raises RuntimeError with the context’s last error text. Serialize the calls on one runtime. The docstrings give the full contract of each method: help(ovclash.ClashRuntime) prints them, and References in the package lists them with the other references. developer_guide.md gives the runtime rules that both languages share, such as setting a scope.

Run settings#

RunSettings holds the settings that standalone queries commonly tune: the tolerance, the time range (set_times, start_time, end_time, time_codes_per_second), point clouds, duplicate search, full-scene traversal, invisible prims, the depth mode, threading (single_threaded, new_task_manager, nb_tasks) and logging. Names in each API lists its fields, and settings.md gives each field’s default, unit and effect, beside the matching C and Suite settings.

  • set_run_settings(settings, **changes) applies settings, or RunSettings() when you omit it, with the keyword changes on top. It does not merge with the settings that the runtime already holds, so every field that you do not pass returns to its default. To change one field and keep the rest, pass runtime.get_run_settings() as the base.

  • nb_tasks must be 1 to 255 when new_task_manager is False and single_threaded is not set. Otherwise any unsigned 32-bit value is accepted, and the new task manager ignores it.

  • A dynamic query (set_times=True with end_time above start_time) drops overlaps between two meshes whose transforms are not animated. RunSettings has no field for this engine default. Run a static query to find those overlaps.

  • use_usdrt has no effect.

  • numpy(), warp() and DLPack (np.from_dlpack(view), torch.from_dlpack(view)) hand the buffer over without copying. numpy() and DLPack need NumPy, and warp() needs warp-lang; the viewer extra installs both. tolist() copies a buffer without either.

  • Close a report when you are done, or use it as a context manager.

  • The runtime closes open reports itself before it changes its stage, settings, scope or pipeline, and on reset() and destroy().

Asynchronous runs#

run_async() starts the pipeline on a native worker and returns an AsyncPipeline. This code replaces runtime.run_pipeline() and the result loop of the first query:

import time

pipeline = runtime.run_async()
running, step = pipeline.poll()
while running:  # drive the loop by the running flag, not by step.finished
    print(f"{step.progress:.0%} {step.name}")
    time.sleep(0.05)
    running, step = pipeline.poll()
pipeline.finish()  # raises RuntimeError when the run failed or was cancelled
print(runtime.get_overlap_count())

Until you call finish() or cancel(), most runtime methods raise RuntimeError. A cancelled run can report zero overlaps, so check is_cancelled() before you read zero as clash-free. async_pipelines.md describes the whole lifecycle.

ovclash_suite#

ovclash_suite is the Suite API. It keeps the legacy clash object model where practical:

  • ClashDetection drives stage loading, settings, scopes, pipeline execution, overlap processing and reports.

  • ClashQuery, ClashInfo, ClashFrameInfo and PointCloudSettings keep the legacy model names and serialization shape.

  • ClashData is the facade over a store. By default it creates and owns a ClashDataSerializerSqlite. That serializer opens .ovclashdb databases and legacy .clashDetection containers by path. No store is loaded from a USD stage.

  • ClashDataSerializerDirectory stores the same records as readable JSON files, one file per record.

  • export_to_html(title, subtitle, column_defs, rows, additional_info=None) and export_to_json(column_defs, rows, additional_info=None) are module-level functions, not methods. They return the document as UTF-8 bytes. Each ExportColumnDef in column_defs describes one column; Python API lists its fields.

persistence.md helps you choose a store and describes both, sqlite_serializer.md and directory_serializer.md describe each store’s format, and export.md describes the reports.

This example runs a query, saves its results, reads them back and exports them as JSON. The object model lists the fields of ClashQuery and ClashInfo:

from contextlib import closing
from pathlib import Path

import ovclash
from ovclash_suite import ClashData, ClashDetection, ClashQuery, ExportColumnDef, SettingId, export_to_json

stage = Path(ovclash.__file__).parent / "samples" / "data" / "time_sampled.usda"
query = ClashQuery(
    query_name="Cube vs Plane",
    object_a_path="/Root/Xform_Primitives/Cube",
    object_b_path="/Root/Xform_Primitives/Plane",
    clash_detect_settings={SettingId.SETTING_TOLERANCE.name: 0.0},
)
clash = ClashDetection()
data = ClashData()  # owns a SQLite serializer
try:
    data.open("results.ovclashdb")
    data.insert_query(query)  # assigns query.identifier
    clash.open_stage(str(stage))
    clash.set_settings(query.clash_detect_settings)
    clash.set_scope_paths([query.object_a_path], [query.object_b_path])
    clash.run_pipeline()
    with closing(clash.fetch_and_save_overlaps(None, data, query)) as fetch:
        for progress in fetch:
            pass
    clashes = data.find_all_overlaps_by_query_id(query.identifier, False)
    rows = [[info.object_a_path, info.object_b_path, info.state.name] for info in clashes.values()]
    columns = [ExportColumnDef(0, "Object A"), ExportColumnDef(1, "Object B"), ExportColumnDef(2, "State")]
    print(export_to_json(columns, rows).decode("utf-8"))
finally:
    data.destroy()
    clash.destroy()

Query settings keys#

Key a ClashQuery’s settings by the SettingId member name, as in the example. The query stores its settings as JSON. A SettingId or integer key becomes a decimal string there, and later lookups ignore it. ClashDetection.set_settings() also accepts SettingId members and their integer values as keys. It ignores an unknown key without an error. Names in each API lists every SettingId key, and settings.md gives its default.

Ownership and errors#

  • Native failures raise Python exceptions that carry the native last-error text.

  • AsyncPipeline and AsyncFetchAndSave are context managers.

  • ClashDetection, ClashData and the built-in serializers are not context managers. Release each with destroy().

  • ClashData.destroy() only closes a serializer that you passed in. That serializer stays yours to destroy.

Some legacy ClashData and ClashQuery methods report a failure through their return value instead of raising. Failures that do not raise lists them and the failures that do raise.

Fetching Suite runtime results#

ClashDetection.fetch_and_save_overlaps(stage, data, query), the fetch-and-save entry point, saves the results of the completed run for query into an open store. The store is a ClashData or a serializer. stage is kept for compatibility and can be None; the results come from the runtime.

The method is a lazy generator that yields progress:

  • The argument checks, the native start and the snapshot of the runtime’s threading settings happen on the first iteration, not when you call the method.

  • Each step handles at most 1,024 frame reports and stops once it reaches about 8 MiB of report payload. One indivisible report can exceed that bound, and a long overlap spans several steps.

  • The final 1.0 yield follows a successful commit.

  • An optional progress_callback receives (written, total) counts. written equal to total does not mean that the results are committed.

  • The query’s SETTING_DUP_MESHES decides whether duplicates are saved. The runtime’s duplicate-only detection setting does not.

Iterate to the end, or close the iterator when you stop early, for example with contextlib.closing. Until then, the iterator reserves the runtime and the built-in store, and conflicting changes and lifecycle calls fail. Close an abandoned iterator before you close or destroy either owner. Serialize the calls that share a runtime or a store.

With async_mode=True, initialization, writes and cleanup run on a native worker:

  • Custom serializer callbacks run on that worker.

  • Progress, modification and timing callbacks stay on the iterating thread.

  • While the fetch is live, reads of the runtime and of the built-in store fail too.

  • Stopping the iteration without closing leaves the worker running. Closing requests cancellation and waits for the worker.

  • Cancellation can race completion. It does not undo a completed commit.

For explicit polling, ClashDetection.run_async_fetch_and_save(stage, data, query) returns an AsyncFetchAndSave context manager. It has is_running(), get_step_data(), get_counts() (which returns (written, total, initialized)), get_last_error(), finish(), cancel() and close().

  • Finish asynchronous detection before you start a fetch.

  • Close the fetch before you read the store.

  • Close it with close() or a with block, not through garbage collection, so that cleanup is timely and its errors are visible.

Fetch-and-save is not all-or-nothing for every failure. Saving detection results gives the outcome of each failure, and how to publish results only after complete success.

Clash states#

By default, a fetch updates the stored clash states as Clash states describes: re-detected clashes become ACTIVE, an unchanged APPROVED clash keeps its approval, and clashes that are no longer detected become RESOLVED. The same flag controls the ACTIVE update in process_overlap() and process_duplicate(). To keep the stored states, clear the flag before you start the fetch:

from omni.physxclashdetectioncore.config import ExtensionConfig

ExtensionConfig.update_clash_states_after_detection = False

Custom serializers#

A custom serializer derives from AbstractClashDataSerializer and must override fetch_transaction(operation). That method handles the operations FETCH_BEGIN, FETCH_COMMIT and FETCH_ROLLBACK, and the savepoints FETCH_BEGIN_OVERLAP, FETCH_END_OVERLAP and FETCH_ABORT_OVERLAP, with the semantics that Custom stores gives. Without that override, fetching raises NotImplementedError before any work starts, because rollback cannot be emulated through the CRUD methods.

For long APPROVED histories, a SQL-backed store should also override fetch_iter_saved_frames(identifier, first_frame_offset=0) with a forward cursor:

  • The cursor yields owned frames in persisted order and has a close() method.

  • The fetch may close the cursor and reopen it at a nonzero offset around writes.

  • The default implementation issues one ranged read per frame.

The docstrings of AbstractClashDataSerializer and its fetch_* hooks give the full contract; References in the package says how to read them. Numeric fidelity describes which numeric values each store keeps exactly.

omni.physxclashdetectioncore#

omni.physxclashdetectioncore exposes the ovclash_suite API under the Kit extension’s module names, for code that you migrate from Kit. New code imports ovclash_suite.

  • A few upstream names are absent.

  • The USD-dependent helpers in its usd_utils module raise NotImplementedError.

  • help(omni.physxclashdetectioncore) lists every gap, and What does not summarizes them.

kit_compatibility.md describes the porting shim.

Comparing ovstage matrix decompositions#

By default, the ovstage backend decomposes mesh matrices with OpenUSD-compatible math. To compare with the original ovclash math without rebuilding, select it on a ClashRuntime. Here runtime is the runtime of the first query, and these lines replace its runtime.run_pipeline() call:

runtime.set_ovstage_matrix_decomposition("ovclash")
runtime.run_pipeline()
runtime.set_ovstage_matrix_decomposition("openusd")  # restore the default
runtime.run_pipeline()

  • runtime.get_ovstage_matrix_decomposition() returns the selection.

  • The mode belongs to one context. It survives reset() and stage replacement.

  • Changing the mode clears existing results, closes open reports and discards the pipeline. The next run_pipeline() or run_async() recreates it.

  • Selecting the current mode again changes nothing.

  • Finish any outstanding async handle first, even when its worker has stopped or the mode is unchanged.

  • Any other name raises ValueError.

The ovclash math can change zero-tolerance clash membership and report payloads. Raw reported world matrices and point-cloud scaling do not change. In both modes, these values fail the affected query instead of being normalized: non-finite or out-of-range matrix values, and invalid resulting poses or scales, including non-unit rotation quaternions.

C callers include <ovclash/ovclash_ovstage.h>, release borrowed reports, and call ovclash_ovstage_set_matrix_decomposition(context, OVCLASH_OVSTAGE_MATRIX_DECOMPOSITION_OVCLASH). OVCLASH_OVSTAGE_MATRIX_DECOMPOSITION_OPENUSD restores the default. Create a new pipeline for the next run. These controls exist only with ovstage, and they do not switch the scene backend. The Suite API, in Python and in C, has no equivalent control. ovstage_integration.md covers the other ovstage-only entry points.

Native library lookup#

Importing ovclash, ovclash_suite or omni.physxclashdetectioncore loads the native library once per process. The packages look for it in this order:

  1. OVCLASH_SUITE_LIB, else OVCLASH_LIB. The value must be the absolute path of the library; a relative path is rejected.

  2. The library bundled in the installed ovclash package. Only the wheel bundles one. The SDK archive’s Python packages need OVCLASH_LIB.

  3. The bare library name, through the platform’s library search. This step runs only when OVCLASH_ALLOW_BARE_LIBRARY_LOAD is enabled, and it is for development only.

The import raises OSError when it cannot load the library. It raises RuntimeError when the library’s version differs from the version of the Python package.

The ovstage runtime#

  • The wheel uses the ovstage package that pip installed as its dependency. It ignores OVCLASH_OVSTAGE_PACKAGE_DIR.

  • The SDK archive does not bundle ovstage. When OVCLASH_SUITE_LIB or OVCLASH_LIB names its library, the packages use the ovstage that the SDK archive’s requirements.txt pins, as installed for the running interpreter.

  • With the SDK archive, OVCLASH_OVSTAGE_PACKAGE_DIR selects another installation instead. Set it to the absolute path of that installation’s ovstage package directory.

  • With the SDK archive, the selected ovstage must be exactly the pinned version, or the import raises OSError.

Process environment#

Loading prepares the process for the runtime:

  • It prepends the runtime’s OpenUSD plugin directories to OV_PXR_PLUGINPATH_2511. It also prepends them to PXR_PLUGINPATH_NAME when the runtime’s OpenUSD is not namespaced.

  • On Windows, it adds the runtime’s directories to PATH and to the DLL search path, followed by the directories that OVCLASH_DLL_DIRS lists, separated by ;.

  • With the wheel, it sets OVSTAGE_LIBRARY_PATH_HINT when the variable is unset. With the SDK archive, it replaces an inherited value with the directory of the selected ovstage.

  • On Linux, it loads the ovstage libraries into the global symbol namespace.

These changes affect the whole process. Child processes inherit the environment variables.

USD coexistence#

ovclash has no OpenUSD linkage of its own: it reads stages through the ovstage API, and the pinned ovstage runtime carries a namespaced OpenUSD. That OpenUSD reads its plugin registry from OV_PXR_PLUGINPATH_2511, so the packages publish the registry only there. An unnamespaced OpenUSD, such as the usd-core wheel, reads PXR_PLUGINPATH_NAME instead and does not load that registry.

  • Keep the ovstage plugin directory out of PXR_PLUGINPATH_NAME when an unnamespaced OpenUSD shares the process. That OpenUSD would read the variable and then fail to declare its own schema types.

  • Install usd-core only for code that imports pxr itself, through the viewer-openusd extra. A query needs no Python pxr.

When another component in your process already manages the OpenUSD plugin paths, set OVCLASH_DISABLE_BUNDLED_PLUGIN_PATHS=1:

  • The packages then add nothing to PXR_PLUGINPATH_NAME or OV_PXR_PLUGINPATH_2511.

  • On Windows, they also leave the plugin directories of the ovclash payload out of the DLL search path.

  • With the wheel, they still add the ovstage package’s runtime and plugin directories to the DLL search path.

  • The native library does not read this variable.
