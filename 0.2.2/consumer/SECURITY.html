Security#

NVIDIA is dedicated to the security and trust of its software products and services, including all source code repositories it manages.

Report a suspected security vulnerability in ovclash, the NVIDIA clash detection library for USD scenes, to NVIDIA PSIRT (Product Security Incident Response Team). Do not report security vulnerabilities through the usual NVIDIA support channel or a public issue tracker.

Report a vulnerability#

Use one of these channels:

  • Web: the NVIDIA Vulnerability Disclosure Program form.

  • Email: psirt@nvidia.com. Encrypt the message with the NVIDIA public PGP key.

NVIDIA’s Report Security Vulnerability page is the authoritative list of reporting channels.

What to include#

  • The product name and the version or branch that contains the vulnerability. For ovclash:

    • the version that python -m ovclash --version or ovclash_get_version_string() reports;

    • whether you installed the wheel or the SDK archive;

    • the contents of ovclash-build-provenance.json from the package root. It names the source revision, the backend and the pinned ovstage version.

  • The type of vulnerability, for example code execution, denial of service or buffer overflow.

  • Instructions to reproduce the vulnerability.

  • Proof-of-concept or exploit code.

  • The potential impact, including how an attacker could exploit the vulnerability.

Disclosure and acknowledgement#

NVIDIA acknowledges externally reported security issues that it resolves under its coordinated vulnerability disclosure policy. The PSIRT policies page describes that policy.

Using ovclash safely#

ovclash runs native code inside your process and reads files and environment variables that you give it. Keep these inputs under your control.

Environment variables#

These variables change what ovclash loads, searches or downloads. Set each only to a value that you control. A flag is enabled by any value other than empty, 0, false, off or no.

Variable

Values

Required

Default

Effect

OVCLASH_LIB, OVCLASH_SUITE_LIB

The absolute path of the native library

With the SDK archive’s Python packages

Unset: the wheel loads the library it bundles

The Python packages load this library and run it in your process. A relative path is rejected. Point it only at a library that you trust.

OVCLASH_ALLOW_BARE_LIBRARY_LOAD

Flag

No

Off

The import loads the first library that the platform’s search finds under the bare library name. It is for development only; do not set it in a deployment.

OVCLASH_DLL_DIRS

Directories separated by ;

No

Unset

Windows only. Adds the directories to the DLL search path. List only directories that untrusted users cannot write.

OVCLASH_OMNI_CLIENT_RETRY_MAX_MS

Milliseconds, an unsigned 32-bit decimal integer

No

0: fail at once

How long the ovstage runtime’s omni client, the Omniverse client library inside ovstage, keeps reconnecting to an unreachable omniverse:// host. An invalid value is reported on stderr and treated as 0.

OVCLASH_INDEX_URL

A package index URL

No

Unset: pip’s configuration selects the index

Read only by run_custom_clash, the launcher of The Clash Processor. The index from which it installs the ovclash wheel when it creates its virtual environment. Name only an index that you trust.

Environment variables lists every variable that ovclash reads.

Native library and search paths#

  • Importing ovclash prepends the runtime’s OpenUSD plugin directories to OV_PXR_PLUGINPATH_2511, and on Windows adds the runtime’s directories to PATH and to the DLL search path. Child processes inherit these variables. The runtime loads plugins from the plugin-path directories, so keep the installed ovclash and ovstage packages in directories that untrusted users cannot write.

Native library lookup describes the lookup order.

Input files#

  • open_stage() in Python and ovclash_open_stage() in C accept only an existing local file. They reject asset URIs.

  • The layers of a stage can still reference omniverse:// assets. The ovstage runtime’s omni client resolves them over the network while the stage loads. OVCLASH_OMNI_CLIENT_RETRY_MAX_MS limits how long it keeps reconnecting to an unreachable host; the default, 0, fails at once.

  • Treat stages, .ovclashdb databases (the SQLite stores of the Suite API), legacy .clashDetection containers and directory stores from other parties as untrusted input.

  • Probe a legacy container with probe_legacy_clash_detection_file() (in C, ovclash_suite_probe_legacy_clash_detection_file()) before you open it. The probe reads only the header bytes. It does not open the SQLite database or migrate a schema.

  • A directory store rejects symbolic links in its path and inside the store. On Windows it rejects directory junctions and volume mount points the same way, so a volume mounted only into a folder cannot hold a store. Pass a physical path; see Store path.

Sample launchers#

  • The Python sample launchers can install the pinned ovstage wheel with pip into a per-user cached virtual environment; samples.md describes when. pip applies your PIP_* variables and pip configuration, including the package index.

  • run_custom_clash can install the ovclash wheel into a virtual environment from the package index that OVCLASH_INDEX_URL names, else from the index that your pip configuration selects.

  • Point these installs only at package indexes that you trust.

Exported reports#

export_to_html() in Python, and ovclash_suite_export_rows_html() and ovclash_suite_export_rows_html_text() in C, escape the title, the subtitle, the column names, the cells and the metadata that they write. The JSON export writes the same values as JSON strings.
