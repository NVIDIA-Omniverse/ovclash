Changelog#

All notable changes to the ovclash public surface — the canonical C ABI (<ovclash/ovclash.h>), the Suite C ABI (<ovclash_suite/*.h>), and the ovclash / ovclash_suite / omni.physxclashdetectioncore Python packages.

The version here is the one in VERSION and python/ovclash/python/suite/_version.py, which must move together: the Python loader rejects a native library whose version disagrees. While the product is pre-1.0, breaking changes may land in a minor or patch release; each one is called out below.

Released entry-point removals go through a deprecation cycle, from the first release after this note. A released entry point that is going away is deprecated in a 0.x.N release — it keeps working, and its declaration carries a message naming both its replacement and the release that removes it — and is removed no earlier than 0.(x+1).0, one minor cycle later. The replacement is added alongside with a _v2 (or higher) suffix rather than by changing the old signature in place. A release that deprecates or removes an entry point carries a ### Deprecated section listing each one. This policy applies only to APIs shipped in a release. Unreleased APIs may change in place without compatibility aliases, version suffixes or a version bump.

SemVer asks for none of that below 1.0; it is a commitment on top of the pre-1.0 allowance above. No breaking change recorded below went through the cycle, and the deprecation marker does not exist in the headers yet: 0.1.3 moved the canonical header, changed every canonical entry point’s return type in place and removed ovclash_set_use_USDRT() in one release, and its ovclash_result_t change alters a transparent type’s layout rather than removing an entry point.

This file records what changed for a consumer. Internal refactors, test-only changes and performance work that does not alter behaviour are summarised, not enumerated.

[0.2.2] - Date 2026-10-22#

Changed#

  • The skill catalog is skills/README.md instead of SKILLS.md. The wheel and the SDK archive ship it inside skills/, next to the skills it lists, and no longer ship SKILLS.md at the package root. The catalog now also says how an agent loads the skills: point it at the installed skills/ folder, because a skill folder copied on its own loses its links to the documentation, the samples and the other skills. Update a script or an agent configuration that reads SKILLS.md.

  • The SDK archive ships the consumer documentation in docs/consumer/ instead of docs/. The pages, the changelog included, keep their names: docs/settings.md is now docs/consumer/settings.md, and the rendered site, where an archive has one, stays in docs/html/. The (SDK archive) links in the skills, the sample READMEs and the package READMEs point to the new paths, so they now also resolve in the source repository. Update a script or a bookmark that opens a page under docs/. The wheel still ships no documentation pages.

Fixed#

  • Saved duplicate overlaps store both objects’ world matrices. The frame of a duplicate overlap held all-zero object_0_matrix and object_1_matrix in SQLite and JSON directory stores, so the record could not place either object. Fetch-and-save and ClashDetection.process_duplicate() now store each object’s local-to-world matrix at the time the duplicate was detected, as for every other frame. A fetch fails instead of storing a matrix it could not read. A duplicate that an earlier version saved and approved compares unequal once, so with clash-state updates on, the Python default, it becomes ACTIVE again on its next fetch.

  • The Clash Processor no longer replaces a --clashdb file that it cannot read. Both the Python and the C++ processor deleted an existing store file that they had no permission to read, such as a renamed legacy .clashDetection container, and wrote a new store in its place. They now stop with exit status 1 and change nothing; the message says that the file cannot be read, so the processor cannot check that it holds no legacy container. A missing file or a readable one behaves as before.

  • The Python samples no longer stop when the console cannot print a character. The Clash Processor, clash_api_python.py and the legacy .clashDetection sample exited with UnicodeEncodeError before they saved anything when a comment, query name or path held a character that the output encoding cannot write, as with redirected output on Windows. They now print such a character escaped, and the stores keep it exactly.

  • ovclash_suite.html_escape() keeps an embedded NUL character and the text after it. It returned only the text before the first NUL. The C function ovclash_suite_html_escape() was not affected.

Documented#

  • omni.physxclashdetectioncore has no data_file_damaged member. In Kit, ClashData, AbstractClashDataSerializer and ClashDataSerializerSqlite report through this flag that SQLite found the database file corrupt or not a database. The compatibility package does not provide it, and the Kit compatibility page now lists it as a gap. ovclash raises instead: open() raises RuntimeError with SQLite’s reason when it cannot inspect the file, and a read that reaches a damaged page raises too. Ported code can test for the member with hasattr.

  • The wheel ships no documentation pages, and its README no longer says it does. Only the SDK archive ships the consumer pages, and the documentation site has them all. The wheel README and the documentation landing pages said otherwise. The Markdown that the wheel ships explains once what its “(SDK archive)” label means.

[0.2.0] - Date 2026-10-20#

Added#

  • Suite results can be saved incrementally and into your own storage. <ovclash_suite/ovclash_suite_serializer.h> declares the fetch-and-save C API and the callback table of a custom serializer, with optional frame preparation. A fetch begins with an explicit choice of whether duplicates are persisted, independent of the detection mode, and then advances in bounded steps, so long frame histories and stale-result reconciliation are spread across calls. ovclash_suite_runtime_fetch_and_save_get_counts() reports how many result groups are written and how many will be. Written results can still be pending, so equal counts do not mean committed. Python Suite serializers use the same lifecycle with the saved query’s duplicate setting, and ClashDetection.fetch_and_save_overlaps() takes a progress_callback that receives (written, total) after each step.

  • ovclash_suite_runtime_fetch_and_save_async() runs a whole fetch on a background worker. It returns an ovclash_suite_fetch_async_t. Poll it with ovclash_suite_fetch_async_get_step_data() and ovclash_suite_fetch_async_get_counts(), then call ovclash_suite_fetch_async_finish() and ovclash_suite_fetch_async_destroy(). In Python, ClashDetection.run_async_fetch_and_save() returns an AsyncFetchAndSave, and fetch_and_save_overlaps(..., async_mode=True) yields progress while it polls.

  • A fetch keeps the runtime and its destination reserved until the fetch is destroyed, after completion or failure; for an asynchronous fetch into a built-in store that includes reads. Conflicting mutation and lifecycle calls fail without invalidating any handle. Abandoning a fetch restores an incomplete overlap and keeps completed pending work, unless the abort fails and the whole transaction rolls back.

  • ovclash_suite_data_get_overlaps_by_query() opens a forward-only cursor over the overlap headers of a query. Each header carries its frame count; frames are not loaded. Advance the cursor with ovclash_suite_overlap_cursor_next() and destroy it with ovclash_suite_overlap_cursor_destroy() before you close the data handle. A live cursor blocks store lifecycle changes.

  • Suite stores can be a folder of readable JSON files. ovclash_suite_data_create_directory() and ClashDataSerializerDirectory (in ovclash_suite and omni.physxclashdetectioncore) create a store whose path names a folder, with one JSON file per query, point-cloud setting, overlap and frame. Every data, cursor and fetch-and-save call accepts it, and one handle at a time can open a folder. Symbolic links, Windows junctions and volume mount points in its path or inside it are rejected, so a volume mounted only into a folder needs a drive letter to hold a store. An unnamed store is created in a new private temporary folder. The processor samples take --clashdir FOLDER, alone or with --clashdb FILE, and docs/directory_serializer.md describes the format.

  • Read the open stage’s own timeline. ovclash_get_stage_timeline_data(), ovclash_suite_get_stage_timeline_data(), ClashRuntime.get_stage_timeline_data() and ovclash_suite.ClashDetection.get_stage_timeline() return the stage’s start and end time codes, timeCodesPerSecond and framesPerSecond, without pxr. The new types are ovclash_stage_timeline_data_t, ovclash_suite_stage_timeline_data_t, StageTimelineData and StageTimeline. ClashDetection.set_settings() takes a keyword-only time_codes_per_second that sets the sampling rate of a dynamic run; a value that is not positive raises ValueError. Query times stay in seconds.

  • A runtime can borrow an ovstage Stage that your application already owns, instead of opening a file. The runtime reads the Stage as its owner populated it, unsaved edits included, and detaching never destroys it. The calls are ovclash_ovstage_attach_stage() and ovclash_ovstage_detach_stage() in the new <ovclash/ovclash_ovstage.h>, ovclash_suite_attach_ovstage() and ovclash_suite_detach_ovstage() in the new <ovclash_suite/ovclash_suite_ovstage.h>, and attach_ovstage() / detach_ovstage() on ovclash.ClashRuntime and ovclash_suite.ClashDetection. The ovclash_ovstage_binding_t descriptor carries the Stage, its timeline metadata and an optional evaluate_time callback. Run your own Stage creation, population, edits and destruction through ovclash_ovstage_run_owner_operation(), ovclash_suite_run_ovstage_owner_operation() or ovclash_suite.run_ovstage_owner_operation(), so they never overlap clash work.

  • An attached ovstage Stage can leave time evaluation to ovclash. Set the optional composition field of ovclash_ovstage_binding_t to an ovclash_ovstage_composition_t that names the root you opened (a path, a URL or USDA text) and the USDA texts you merged at /, earliest first. In Python, pass composition_root, composition_layers and composition_root_is_usda to ovclash.ClashRuntime.attach_ovstage() or ovclash_suite.ClashDetection.attach_ovstage(). ovclash then evaluates every finite time in private ovstage populations of that composition, and never calls evaluate_time or advances your Stage. Keep the root and every file it references unchanged on disk until you detach.

  • Choose how ovstage decomposes mesh matrices. ovclash_ovstage_set_matrix_decomposition() and ovclash_ovstage_get_matrix_decomposition(), and ClashRuntime.set_ovstage_matrix_decomposition() / get_ovstage_matrix_decomposition() in Python, select the mode of one context. The default follows USD’s own decomposition (see Changed). OVCLASH_OVSTAGE_MATRIX_DECOMPOSITION_OVCLASH (Python "ovclash") restores the math of earlier releases. Changing the mode clears the results and the pipeline, so release your reports first. The mode survives a reset and a stage replacement.

  • ovclash.RunSettings gains new_task_manager (default True) and nb_tasks (default 128), which round-trip through the native settings. With the legacy task manager selected, ClashRuntime.set_run_settings() rejects an nb_tasks outside 1 to 255 with ValueError and changes nothing. The clash_api samples and the clash_suite_api processors take --single-threaded, --multi-threaded and --num-tasks N. The clash_api samples stay single-threaded by default, and the processors multithreaded.

  • New shipped agent skill ovclash-clash-processor. It covers running clash queries on your own stages without writing code, with run_custom_clash or clash_suite_api_python.py: scoping, static and time-sampled checks, stores, reports, exit statuses and Windows quoting. SKILLS.md lists it beside the four API skills.

  • The wheel and the SDK archive carry ovclash-build-provenance.json, which records the source and build identity, the backend, the product version and the pinned dependency versions. The wheel metadata lists the project’s homepage, repository, documentation, issue tracker and changelog.

Changed#

  • ovstage runs its heavy phases in parallel, and the threading controls now govern it. Mesh preparation and cooking, poses and bounds, the broad and narrow phases, report extraction and Suite result fetching use the selected scheduler. Before, ovstage stored ovclash_set_single_threaded(), ovclash_set_new_task_manager(), ovclash_set_nb_tasks() and the matching Suite and Python settings without using them. Single-threaded mode forces serial work. Otherwise the new task manager, the default, uses a shared worker pool, and with it turned off at most nb_tasks threads run. A time-sampled query also reads the next window of transforms ahead and reuses the collision result of a sample whose inputs exactly match the previous one. Overlap membership, per-pair data and the ovclash_get_overlap_data() order match a serial run. You can change the controls between detection and fetching.

  • ovclash.RunSettings.single_threaded now defaults to False, as a fresh native context and ovclash_suite already did, so the canonical Python API runs in parallel without opting in. python -m ovclash is multi-threaded by default and gains --single-threaded; --multi-threaded is still accepted and has no effect. Pass single_threaded=True or --single-threaded for a serial run. Results do not change.

  • ovstage now follows USD’s own matrix decomposition by default, so a few zero-tolerance results can change. The previous math could split a mirrored (negatively scaled) transform differently from USD. At zero tolerance it then reported or missed a handful of grazing pairs, and their faces and outlines could differ. Select OVCLASH_OVSTAGE_MATRIX_DECOMPOSITION_OVCLASH to reproduce earlier results.

  • ovstage samples a dynamic range exactly as documented. Sampling starts at startTime and adds 1/timeCodesPerSecond until the next time passes endTime. Earlier releases moved a sample that overshot endTime by a rounding error back onto endTime. That sample is now dropped, so such a range can have one sample fewer. ovclash_create_pipeline() captures the timing settings and rejects a range whose sample count does not fit, keeping the previous pipeline.

  • ovstage decides which meshes move from their authored transform animation. By default, ovclash_set_purge_permanent_static_overlaps() drops pairs of two static meshes from a time-sampled query. A mesh now counts as moving when its own transform or an ancestor’s has more than one effective time sample, even if every sample holds the same value. Such pairs were dropped before and are now reported. A mesh whose animation cannot be resolved counts as moving.

  • Asynchronous runs on ovstage. ovclash_finish_pipeline() returns OVCLASH_STATUS_ERROR whenever cancellation was requested before finish, even if the worker had completed. The worker no longer waits 25 ms before it starts, and it runs with the floating-point rounding, denormal and exception-mask settings the calling thread had at launch. When a sampled step fails, every overlap the run collected is discarded, so restart at step 0 before you use results.

  • Asynchronous progress on ovstage moves within a step. ovclash_get_pipeline_step_data_async() and AsyncPipeline.step_data() report a fractional stepProgress / step_progress from counted work, and progress includes it. Before, ovstage reported whole steps only. An async step name can carry the current operation after the phase name, so match names by prefix. Synchronous step names are unchanged, and neither value is a time estimate.

  • An approved clash stays approved when a new run detects exactly the same result. With state updates on, fetch-and-save still sets every re-detected clash to ACTIVE and every absent one to RESOLVED. State updates are on when C passes a nonzero resolve_stale, and by default in Python. The exception is an APPROVED clash whose detected header and complete ordered frames are unchanged: it stays APPROVED. Review fields, timestamps and user penetration-depth annotations are not compared. A custom C store takes part through the optional ovclash_suite_fetch_saved_data_reader_t of ovclash_suite_runtime_fetch_and_save_begin_with_reader() and ovclash_suite_runtime_fetch_and_save_async_with_reader(); without one, its re-detected clashes become ACTIVE. To keep every stored state, pass resolve_stale 0, or set omni.physxclashdetectioncore.config.ExtensionConfig.update_clash_states_after_detection = False.

  • Collision outline segments have a fixed direction. Each segment of collidingSegments, and of the Suite’s stored outlines, points along an axis whose first nonzero x, y or z component is negative. Mesh order, query order and triangle winding no longer change it. Endpoint coordinates are unchanged, but a segment can come back with its endpoints swapped compared with earlier releases. Compare outlines as unordered segments.

  • On ovstage, ovclash_is_out_of_memory() now reports allocation failures; it always returned 0 there before. The flag is set when a required allocation fails in a call or in the async worker. It survives ovclash_finish_pipeline() and clears on reset, on a stage-open attempt and on a new run. While it is set, ovclash_get_last_error() returns a fixed message.

  • Opening a stage that references an unreachable omniverse:// host no longer stalls for about two minutes. On ovstage, payloads, references, sublayers and MDL assets on such a host now fail at once, and their geometry is missing from the results. To wait through a short server outage, set OVCLASH_OMNI_CLIENT_RETRY_MAX_MS to a positive number of milliseconds. ovclash applies it once per process to the shared client, so it also governs your own reads through that client, including those of a Stage you attach.

  • ovstage is faster and leaner on large and instanced stages. Mesh discovery does less repeated work. Subcomponent filtering reuses the stage already read instead of opening the file a second time. Repeated ovclash_get_prim_matrix() calls at advancing times after a run are much faster. The sampled-transform cache can hold up to 1 GiB (was 256 MiB), plus up to 8 MiB for reused collision results. Results are unchanged.

  • Saving and reading Suite results is faster. Fetch-and-save extracts, encodes and writes results in native code instead of making a Python round trip per overlap, and reuses its SQLite statements. Reading every query or point-cloud setting of a large SQLite store in index order no longer costs time that grows with the square of the row count, and reading frames into Python copies less. During bulk writes the SQLite page cache is raised to at least 64 MiB (was 32 MiB) and restored afterwards, so each active writer can use up to 32 MiB more memory.

  • Immediate depth queries on ovstage reuse geometry the context already loaded. ovclash_imm_compute_max_local_depth(), ovclash_imm_depenetrate_meshes(), ovclash_suite_compute_max_local_depth() and ovclash_suite_compute_penetration_depth() no longer read the file again on every call once a run has loaded that geometry. Repeated queries are faster, but they no longer see edits saved to the file after it was opened. Call ovclash_open_stage() again to pick those up.

  • Opening a stage drops the scope set for the previous stage, and a reset keeps it. ovclash_suite_open_stage() and ClashRuntime.open_stage() clear the scope on success, so the next run no longer searches the old stage’s prim paths; set the scope after opening. The Suite also turns whole-stage selection back on when the run settings enable enable_full_scene. ClashRuntime.reset() keeps the scope, as ovclash_reset_context() does, and a failed open keeps it too. ClashDetection.set_settings() and set_scope() no longer reopen the stage when their stage argument is another spelling of the file already open.

  • ovclash_suite_file_exists(), and with it omni.physxclashdetectioncore.utils.file_exists(), reports only regular files, following symbolic links, on every platform. Before, Linux reported a directory as an existing file, and an unreadable file could be reported as missing.

  • ClashData.fetch_all_queries() and fetch_all_point_cloud_settings() raise RuntimeError when the count or any row cannot be read; they used to return a partial dictionary. get_file_path() on a built-in serializer raises when the path cannot be read instead of returning "".

  • When a with block on ClashRuntime or AsyncPipeline exits because of an exception, it requests cancellation of the active async run before waiting for it. A normal exit still waits for completion. If cleanup also fails, the exception from the block is the one raised.

  • In C++, ovclash_status_t, ovclash_mesh_index_t, ovclash_depenetration_axis_t, ovclash_report_buffer_t and ovclash_max_local_depth_mode_t now declare uint32_t as their underlying type. An out-of-range value stays well defined until the API rejects it, and setters reject one. Sizes and values are unchanged, and C callers see no difference; in C++ these types now promote to unsigned int, not int.

  • Linux builds no longer fuse floating-point multiply-adds, so results on Linux AArch64 can differ from earlier releases in the last bit. Every operation is rounded separately, so Linux x86-64 and AArch64 compute ovclash’s own arithmetic the same way. On AArch64 the default ovstage matrix decomposition now also matches USD’s GfTransform exactly.

  • python -m ovclash and the sample programs explain themselves. Their --help describes what the program does and how to call it, with examples, and --version prints the version; python -m ovclash --version reports the version of the loaded runtime. A normal python -m ovclash run prints its version and purpose on stderr, so stdout still carries only JSON. Help and validation messages are colored in an interactive console.

  • The Suite processors take the sampling rate from the stage and expose every engine setting. Both clash_suite_api processors sample a dynamic run at the open stage’s rate instead of 24 per second; --time-codes-per-second overrides it. They gain --coplanar, --any-hit, --overlap-code, --triangle-limit, --ignore-invisible-prims, --ignore-redundant-overlaps, --subcomponent-filtering, --purge-permanent-static-overlaps, --purge-permanent-overlaps, --compute-max-local-depth, --max-local-depth-mode low|med|high, --discard-touching-contacts, --depth-epsilon, --contact-cutoff, --pose-epsilon, --bounds-epsilon, --area-epsilon, --tight-bounds, --quantized and --tris-per-leaf. Options you do not set keep the engine defaults. The processors also run detection and fetch-and-save asynchronously by default: --async false runs both on the calling thread. The library’s Python fetch API stays synchronous by default.

  • The processor samples print more, so scripts that parse their output need updating. The Clash Processor Arguments: section groups related arguments, has a backend row with the backend the loaded runtime reports, and ends each line with the value’s source, such as (provided), (default) or (engine default). With an output option, saving shows percentage progress under Fetching, serializing and saving results.... Every run prints Clash detection time: and Fetching, serialization and saving time: (or Fetching, serialization and saving: not requested.) before Total elapsed time. The Python processor also prints the times it resolved, such as Resolved static time: <seconds> s, and its cleanup time, and with --logging a [perf] line for each phase and pipeline step.

  • The processor samples reject ambiguous command lines. The positional stage [json [html]] form can no longer be mixed with --stage, --json or --html, and positional paths must come before every option. A stray path is now an error instead of being ignored or taken as the stage or an output path, such as the second half of an unquoted comma-separated --object-a list. run_custom_clash.bat and run_custom_clash.sh treat an option value that is empty or starts with - as missing. Quote search-set lists that contain commas, semicolons or spaces.

  • run_custom_clash says which runtime it uses, and inside an SDK it uses that SDK. Before the processor starts, it prints a line such as Backend: ovstage -- runtime: published wheel in "<venv>". Without --install-root, the copy in an unpacked SDK runs against the SDK it ships in, creates no virtual environment and downloads nothing. The new --wheel option forces the published-wheel route. Every failure while it sets up its virtual environment now exits with status 1 and a message, on Linux as on Windows; a failed pip self-upgrade only warns.

  • The sample launchers run against the package that contains them and set up ovstage themselves. The Python launchers import the ovclash of the SDK or wheel that contains them, even when another ovclash is installed, and ignore an inherited PYTHONPATH. They start from PYTHON, else python3 (python on Windows). When that interpreter lacks the exact pinned ovstage, the launchers and samples/build_samples install it into a per-user cached virtual environment and leave the interpreter’s packages unchanged. The first setup needs pip access to the pinned wheel, and on Debian and Ubuntu also python3-venv. In the SDK, OVCLASH_OVSTAGE_PACKAGE_DIR still selects an installation, which also works offline.

  • The C++ sample launchers build outside the samples/ folder. run_clash_api_cpp, run_clash_suite_api_cpp, run_legacy_clash_detection_cpp and samples/build_samples build under _build/samples/<sample> in the package root, and the Windows SDK launchers under %LOCALAPPDATA%\ovclash\samples\<hash>\<sample>, which avoids compiler path-length failures. OVCLASH_SAMPLE_BUILD_ROOT still selects another directory. A sample build tree records which SDK configured it, so an SDK replaced at the same path is configured from scratch. The C++ sample sources are renamed: clash_api_capi.cpp is now ClashApi.cpp, clash_suite_api_capi.cpp is now ClashSuiteApi.cpp, and legacy_clash_detection_capi.cpp is now LegacyClashDetection.cpp.

  • The SDK archive carries the Python APIs and is named version first. It holds the ovclash, ovclash_suite and omni.physxclashdetectioncore packages under python/, and its Python sample launchers use them with the SDK’s own library. For your own program, add <sdk>/python to PYTHONPATH and set OVCLASH_LIB to the SDK’s library; that program then uses the ovstage installed for its own interpreter, or the one OVCLASH_OVSTAGE_PACKAGE_DIR names, at exactly the pinned version. The archive is now ovclash-<version>-<platform>.zip on Windows and ovclash-<version>-<platform>.tar.gz on Linux; it was ovclash-<platform>-<version>.

  • ovclash-LICENSES.zip in the wheel and the SDK archive also carries the Tomorrow Open Source Technology License 1.0 and the notice for Pixar’s USD Gf math, which the default ovstage matrix decomposition adapts. Pass them on with the other third-party notices when you redistribute.

  • The pinned ovstage runtime moved from 0.2.0.375291 to 0.3.0.1791986420. This build is on public PyPI, so the wheel’s dependency and the SDK’s requirements.txt resolve there. No result change was recorded for the move.

Changed — breaking#

  • The wheel is Python-only; C and C++ development files ship only in the SDK archive. The wheel no longer contains the public headers, the CMake and pkg-config package files, the Windows import library, the C/C++ sample sources, build_samples or the run_*_cpp launchers. It keeps the native library, both Python APIs, the Python samples and their launchers, the documentation and the skills. A C or C++ build that used an installed wheel as its find_package(ovclash) root must switch to the SDK archive for its platform. On Linux the wheel still ships libovclash.so.<major>, so a binary linked against an earlier wheel keeps loading after an in-place upgrade.

  • The SDK archive no longer contains ovstage: install it with pip before you build against it. The archive’s requirements.txt pins the exact ovstage version. From the SDK root, run python -m pip install -r requirements.txt with Python 3.10 or newer. find_package(ovclash) reads that installation through OVCLASH_PYTHON_EXECUTABLE (an absolute path), or the one OVCLASH_OVSTAGE_PACKAGE_DIR names, and takes the ovx headers from it. On Linux, pass --define-variable=ovstage_root=<site-packages>/ovstage to pkg-config. On Windows, add <site-packages>\ovstage\bin and its plugins folder to PATH beside <sdk>\bin. The wheel is unchanged, because pip installs ovstage with it.

  • The wheel no longer ships the omni.physxclashdetectionbake bake helper or its material assets. Bake authoring and visualization are outside the library’s scope, so import omni.physxclashdetectionbake fails against an installed wheel. Take bake from the Kit clash-detection extension, or build your own visualization from clash reports. The omni.physxclashdetectioncore compatibility package and the clash APIs are unchanged.

  • The wheel’s [viewer] extra no longer installs usd-core. ovclash[viewer] and the new ovclash[viewer-ovstage] add NumPy and warp-lang for the zero-copy numpy() and warp() report adapters. Code that imports Python USD (pxr) itself must install the separate extra that adds usd-core==26.5; the wheel README lists it under optional extras. A clash query never needs usd-core.

  • run_custom_clash installs ovclash from pip’s configured index. When it sets up its own virtual environment and OVCLASH_INDEX_URL is not set, the launcher runs a plain pip install ovclash, so pip’s own configuration picks the index: PIP_INDEX_URL, a pip configuration file, or else public PyPI. It used to default to an NVIDIA-internal index. Set OVCLASH_INDEX_URL or PIP_INDEX_URL to an index that serves both ovclash and its pinned ovstage, or pass --install-root DIR for an SDK. An environment that already has ovclash is reused unchanged.

  • Release overlap reports before the next pipeline step, not just before the next run. On ovstage, a sampled step can replace the buffers a report borrows. ClashRuntime.run_pipeline_step() now closes every open OverlapReport, as create_pipeline() and run_async() already did, so copy any buffer you need first, NumPy and DLPack views included. C callers must call ovclash_release_overlap_report() before the next ovclash_run_pipeline_step().

  • ovclash_suite_create_overlap_report() and ovclash_suite_create_clash_info() return the new status OVCLASH_SUITE_STATUS_UNAVAILABLE (2) when a valid record has no report. The report is then null and the views are empty. Extraction, allocation and cancellation failures stay OVCLASH_SUITE_STATUS_ERROR. Code that tests for success keeps working; code that tests for OVCLASH_SUITE_STATUS_ERROR or switches on the status must handle the new value, usually by skipping that record.

  • ClashDetection.fetch_and_save_overlaps() saves through native code and needs a destination. Passing None as clash_data raises ValueError; before, it extracted every overlap and then discarded it. To skip saving, read the results from the runtime instead. A custom AbstractClashDataSerializer must implement fetch_transaction() for the FETCH_* operations, or fetching raises NotImplementedError. The other fetch_* hooks fall back to its record methods, which must raise on failure.

Fixed#

  • A mesh whose transform cannot be decomposed into a valid pose no longer drops out of a query silently. A transform with collinear or degenerate rows, a non-finite value or a magnitude outside the float range used to yield a distorted pose: the pipeline reported success with clashes missing, and an immediate mesh query could overwrite its outputs with a wrong result. On ovstage the run or query now fails, ovclash_get_last_error() reports a Matrix decomposition ... error, Python raises, and an immediate query leaves its outputs unchanged. Correct the transform on the stage. Valid transforms give the same results as before.

  • Heavily instanced stages need far less memory and time on ovstage. Since instance placements became part of queries, memory use and mesh-preparation time grew with the number of placements, and a full-scene query on a stage with thousands of instanceable prims could run out of memory. Both now grow with the amount of unique geometry. Results are unchanged.

  • A static query on ovstage no longer re-reads the whole stage for each mesh whose instance is hidden at time 0. On stages where instanced meshes are visible at the default time but hidden at time 0, every such mesh caused a fresh read of the complete stage, and a query on a large stage could take minutes. Those transforms now come from one shared read.

  • Queries use the stage’s own time rate. On a binary .usd stage without pxr, ovclash_suite.ClashDetection.set_settings() could not read the timeline: a static query silently ran at time 0, and a dynamic range assumed 24 time codes per second, so on a stage authored at another rate the sampled poses were wrong and clashes were missed. The timeline is now read natively, and a dynamic query with both times at 0 takes the stage’s range instead of being refused. ovstage also resolves the rate as USD does: a stage that authors framesPerSecond but not timeCodesPerSecond uses framesPerSecond, where it used 24. A stage whose effective rate is zero, negative or not finite now fails to open on ovstage.

  • The ClashInfo matrix-changed checks compare with the pose at the frame’s time. ClashInfo.check_object_a_matrix_changed() and check_object_b_matrix_changed(), in ovclash_suite and omni.physxclashdetectioncore, passed the frame’s stored time, which is in seconds, to a query that takes a USD time code. On a stage whose time-code rate is not 1, a frame at a nonzero time was compared with the pose at another time, so a check could report a change that did not happen or miss one that did. The time is now converted with the stage’s effective time-code rate, and the checks raise RuntimeError when that rate cannot be read or is not positive and finite.

  • Stages authored in units other than centimeters are prepared at their own scale. The runtime did not read a stage’s metersPerUnit and prepared every mesh as if the stage were in centimeters. It now uses the authored value.

  • ovstage no longer reports an old clash under new paths. Any ovclash_open_stage() attempt, failed or reopening the same path included, and a direct rerun of the mesh-selection step retire the earlier results. After them, ovclash_get_overlap_data(), ovclash_get_duplicated_meshes_data(), depth queries and overlap reports for those results fail as stale, while the counts are kept. ovclash_get_prim_matrix() fails for a prim the stage does not contain instead of answering from the previous run’s selection. When the transform at the requested time cannot be read, it and ovclash_suite_get_prim_matrix() fail with Failed to query prim transform: <prim path> instead of returning the last evaluated sample.

  • Using several ovstage contexts on different threads no longer corrupts the heap. Opening, replacing or releasing stages in different contexts at the same time could rarely crash the process under load. Stage loading and release now run one at a time across the process; queries and clash runs on loaded stages still run in parallel.

  • A moving mesh that touches identical static copies is reported once. With redundant-overlap filtering on (ovclash_set_ignore_redundant_overlaps(), Suite SETTING_IGNORE_REDUNDANT_OVERLAPS) and permanent static overlaps purged, a time-sampled query reported moving mesh C against each identical static copy, as both A/C and B/C. It now keeps one contact with its sampled records, on a pair that the query’s scopes and filters admit. Turn redundant filtering off to keep one contact per copy.

  • On ovstage, collision outlines no longer include segments from tolerance near-misses. A pair that clashes only within the tolerance still reports its faces but has no outline segments; outlines come only from touching or interpenetrating triangles. Outline segments are also computed under the calling thread’s floating-point rounding and denormal modes, unless the context selected OVCLASH_OVSTAGE_MATRIX_DECOMPOSITION_OVCLASH.

  • Subcomponent filtering on ovstage follows USD composition. ovclash_set_subcomponent_filtering() now finds each mesh’s subcomponent from the composed kind values, including kinds authored in referenced, sublayered or binary layers or in a selected variant, and a mesh of an instanced asset resolves per placement. Before, the filter could resolve a different subcomponent and keep or drop the wrong pairs. Duplicate-mesh detection now honors the filter too, so two identical meshes in the same subcomponent are no longer reported as a duplicate pair.

  • Paths that contain an embedded NUL character are rejected instead of cut short. ovclash_open_stage(), ovclash_get_prim_matrix(), ovclash_sdf_path_to_int(), ovclash_set_scope_paths() and every Suite file-path argument now fail before touching anything, including store open, save-as, migration, legacy containers, ovclash_suite_copy_file() and ovclash_suite_delete_file(). Before, such a path was read only up to the NUL, so a call could act on a different file or prim. ovclash_suite_file_exists() reports such a path as no file, and the Python wrappers raise.

  • On Windows, Suite stores, legacy .clashDetection containers and the Suite file helpers handle paths with non-ASCII characters. These UTF-8 paths were decoded with the system code page, so opening, saving, migrating or extracting a store in a folder with an accented name could fail or miss the file.

  • Out-of-range identifiers no longer reach a different record. find_query() and remove_query_by_id() on ClashData and ClashDataSerializerSqlite, and a ClashQuery identifier, silently wrapped a value outside the signed 64-bit range: removing 2**64 + 42 removed saved query 42 and reported success. Such values now raise OverflowError and leave the store unchanged. find_all_overlaps_by_query_id() and fetch_clash_frame_info_by_clash_info_id() cap huge offsets and limits, so an offset of 2**63 no longer starts again from the first row. Refetching into a SQLite store with imported negative overlap keys, -1 included, updates those rows and keeps their annotations.

  • Suite model JSON no longer reports success for values JSON cannot hold. ovclash_suite_query_serialize_json(), ovclash_suite_point_cloud_settings_serialize_json(), ovclash_suite_clash_frame_info_serialize_json() and ovclash_suite_clash_info_serialize_json() fail with a non-finite-value error when any value is NaN or infinite, and leave the buffer and the size untouched. Before, they returned success with text no JSON parser accepts. Negative zero is written as -0.0, so it reads back with its sign.

  • SQLite scalar writes reject NaN instead of silently storing NULL and reading it back as zero.

  • Python data cleanup destroys its owned SQLite handle deterministically. ClashData.close() and commit() raise when the final commit fails and keep the handle for a retry; close() used to swallow that failure. Finalization retries a failed, rolled-back commit once and reports cleanup errors. Fetch iterator cleanup errors stay visible even when iteration completes inside a caller’s exception handler. Abandoning a SQLite fetch reports a new rollback error instead of an unrelated old diagnostic.

  • Custom serializer callbacks must report explicit successful completion for writes, transaction operations, preparation, release and diagnostics. Cleanup drains owned reports and prepared values while preserving the primary failure, and Python handles stay usable when native destruction is rejected by an active lease.

  • Saving a SQLite store under a new path keeps every committed row. ovclash_suite_data_save_as(), ovclash_suite_data_save() with a path, and ClashData.save() / save_as() used to copy the database file, so the copy could miss recently committed results while another connection was reading the store. They now write a SQLite backup that includes committed and pending writes. Saving to the store’s own file or a hard link to it keeps the current store, and a .clashDetection export leaves the current store and path unchanged.

  • is_open() on ClashData and the built-in serializers reports an open unnamed store as open; it returned False whenever the store had no path. When a SQLite query, settings, frame or delete call fails with an internal error, the whole pending transaction is rolled back before the error is reported, so a later commit cannot publish half of that change.

  • Migrating a Suite store checks the target before giving up the current store. ovclash_suite_data_migrate_to_latest() and ClashData.migrate_data_structures_to_latest_version() reject a target that is not a readable regular file, or a SQLite file this process cannot write, and the current store keeps its connection, pending writes and open state. Opening a SQLite store whose path names a directory fails at open on every platform, not at the first write. After a failed open of a .clashDetection path, a write fails instead of creating a plain SQLite database under the container name.

  • ClashData.insert_overlap() and update_overlap() check every frame before writing anything: a frame that cannot be stored raises ValueError and leaves the store unchanged, and an overlap and its frames commit together. get_overlaps_count_by_query_id_grouped_by_state() adds up stored states that map to the same ClashState instead of keeping only the last count.

  • ovclash_suite_set_run_settings() rejects a tolerance, epsilon, contact cutoff or point-size override outside the float range instead of handing the engine an infinite value. ovclash_suite_compute_penetration_depth() rejects a non-finite, zero or overflowing direction instead of returning a meaningless depth.

  • The AsyncPipeline returned by ClashRuntime.run_async() can be used from several threads. A call that overlapped finish() on another thread could use the native handle while finish() freed it. Now is_running(), is_cancelled() and step_data() answer from the last known state, and cancel() and close() wait for that finish() to return. cancel() cannot interrupt a finish() that is already waiting, so cancel first and then finish.

  • Python no longer leaks a native object when creation is interrupted. When an exception such as KeyboardInterrupt arrives while ClashRuntime, Suite ClashDetection, ClashDataSerializerSqlite or an async launch creates its native object, or while an overlap report is returned, the object is released and the original exception is raised.

  • The Clash Processor no longer deletes a legacy .clashDetection container passed as its store. Without --append, clash_suite_api_python.py and the C++ processor deleted the file at the --clashdb path and only then failed to open it, so a Kit-era container named there was lost. Both processors now reject that path, by name in any letter case or by content, before they touch any output. A name match is a command-line error in the Python processor (exit status 2); every other case exits with status 1 and Clash processor failed: --clashdb '<path>' ....

  • The Windows sample launchers forward every argument exactly as typed. A launcher that passes its arguments on to another batch script, as run_custom_clash.bat does when it runs an SDK, dropped an argument that starts with ;, could then eat ! in later arguments, and could not reach a script whose path contains !. A value that cannot be passed on intact, such as one that contains a line break, now stops the launcher with an error instead of arriving cut short.

  • On Windows, samples/build_samples.bat --build-root DIR accepts an existing empty directory, as build_samples.sh already did, and two sample launchers started at the same time with a shared build root no longer fail when both try to create it.

Documented#

  • import ovclash published the ovstage wheel’s namespaced USD plugin registry through the classic PXR_PLUGINPATH_NAME too, so a pip usd-core in the same process raised Tf.ErrorException on its first registry use and the [viewer] workflows failed. It now goes to OV_PXR_PLUGINPATH_2511 only, matching the bundled path.

  • A Linux C consumer of the wheel no longer needs LD_LIBRARY_PATH to start. libovclash.so names an ovstage library as a direct dependency (the libovstage-dynamic.so loader against the pinned runtime), but the wheel’s pinned ovstage lives in a sibling distribution outside every directory the library’s RUNPATH named, so a binary built through the documented find_package path linked cleanly and then died at load with “cannot open shared object file” – and nothing shipped said to set LD_LIBRARY_PATH. The library now carries a RUNPATH entry that resolves to the sibling ovstage package. The SDK layout and Windows were never affected.

  • Serializing settings with a non-finite value now fails instead of returning unparseable JSON. ovclash_suite_run_settings_to_query_settings_json emitted a bare nan / inf and still reported success; it now refuses the struct and names the field, as ovclash_suite_set_run_settings already did. Only a direct C caller could reach it – the Python layer rejects non-finite settings before the call.

  • Assigning ClashQuery.clash_detect_settings a mapping JSON cannot encode raises TypeError instead of silently storing empty settings. Every write path fell back to "" on a serialization failure, the native validator accepts an empty settings blob, and the query then ran – and was persisted – on defaults the caller never asked for, producing a clean-looking clash report. A numpy scalar, Decimal, set or pxr.Gf value in the mapping is a caller bug and is now named at the assignment, which leaves the previous value in place. Reading a store whose settings text is unreadable stays tolerant, but now logs a warning instead of quietly treating the settings as empty.

  • A mesh PhysX cannot cook is no longer dropped silently. It is still skipped rather than failing the run, but the run reported success with that mesh’s overlaps absent – indistinguishable from a clean scene, the only trace a log line behind the off-by-default OVCLASH_SETTINGS_FLAG_LOG. Cooking now records how many meshes were dropped and names the first through ovclash_get_last_error() regardless of that flag, and ovclash_stats_t::nbCookedMeshes below nbMeshes minus nbSharedMeshes is documented as the countable signal. ovstage only; the second half of the trisPerLeaf fix in 0.1.5. ovclash_suite_get_last_error() is not reached – Suite callers compare nb_cooked_meshes with nb_meshes.

  • Ordinary metadata on an ancestor prim no longer makes an unrelated mesh silently stop clashing on the ovstage backend. The root-layer text scrapers track prim paths by counting braces, and a prim-metadata parenthetical such as customData = { ... } contains braces too, so every descendant of such a prim was recorded one level too shallow – and could overwrite an unrelated prim’s entry, replacing a valid mesh’s topology with a degenerate one. That mesh still counted in nbMeshes, cooked to nothing and reported no error, so its clashes simply vanished. customData and assetInfo on group prims are ubiquitous in exported assets, so this needed no exotic input. Braces inside prim-metadata parentheses are now invisible to the brace accounting.

  • The query-settings JSON now keeps full precision. ovclash_suite_run_settings_to_query_settings_json serialized at the iostream default of six significant digits, so a setting did not survive the round trip: a dynamic_end_time of 239/24 came back as 9.95833, and the resulting sample count dropped the final sample of the run. All ten double fields were affected. Parsed values that already fit in six digits are unchanged, but the emitted text is now 17 significant digits, like the rest of the serialized model – the default pose_epsilon and area_epsilon read 9.9999999999999995e-07, not 1e-06. Settings text stored in a .ovclashdb or spliced into an exported query definition changes with it.

  • A plain get_overlap_report(i) now returns the geometry it promises. The default flags value was OverlapReportFlag.DEFAULT, which is 0 and selects no content buffer on this entry point, so the report came back live but with empty faces, outline and points for an overlap that genuinely had them – reading as “this clash touches no geometry”. The default now requests FACES0, FACES1, OUTLINE and POINTS0, matching the Suite’s get_overlap_report2, and an explicit flags value still narrows the work. Asking only for DEFAULT or FACES – the legacy selectors this entry point ignores – raises ValueError instead of returning that empty-but-valid-looking report.

  • ovclash.AsyncPipeline stays pollable after cancel() and after finish(). Both release the native cookie, and poll(), is_running() and step_data() still called through it, so the documented polling loop raised once the run reached either terminal state. is_running() now answers False, and step_data() answers from the last step observed – settled to finished at full progress when the run completed, kept as observed when it was cancelled. A pipeline that was never polled has no step to report and still raises. The canonical package previously kept the opposite contract from ovclash_suite, whose pipelines became pollable after termination in 0.1.5; the two now agree.

  • Python index arguments above UINT32_MAX were silently truncated to 32 bits by ctypes instead of rejected, so get_overlap_record(2**32) returned overlap group 0 and 2**32 + k returned group k – a valid-looking record for a group the caller never asked for. Every c_uint32 index on the canonical and Suite Python APIs now raises OverflowError; the native bounds check still owns in-range values past the count.

Documented#

  • The shipped documentation was audited against the code and corrected where it had drifted. The README claimed the package intentionally omits the Carbonite tasking plugin; that stopped being true at the ovstage 0.2 upgrade – the plugin ships – and the packaged dependency_audit.txt stamped the same stale claim into every build. The C-API agent skill still described the pre-0.1.5 permissive find_package behaviour instead of the hard failure and its OVCLASH_ALLOW_MISSING_OVX escape hatch. Three sample READMEs pointed their --stage examples at the test-fixture directory the packages no longer ship. The Suite C-API skill, the Overview and the Technical Guide were brought back in line with the code as well.

[0.1.5] - Date 2026-09-02#

Changed — breaking#

  • trisPerLeaf above 15 is now rejected. PhysX validates the value against [2,15], so 16 or more failed every mesh cook – and because a failed cook does not fail a pipeline step, the run reported every step successful with zero overlaps on overlapping geometry. The setters and ovclash_suite.RunSettings now accept only 1..15 on both backends. Values below 2 are unchanged: PhysX rejects them too and the existing retry cooks them at 15.

  • find_package(ovclash CONFIG REQUIRED) fails when the ovx include directory cannot be resolved, naming the header and the remedy, instead of reporting success and letting the build fail later on a missing-header #error. Set OVCLASH_ALLOW_MISSING_OVX=ON to keep the old permissive behaviour when the header arrives through compiler flags CMake cannot see.

Changed#

  • Each package ships only its own platform’s sample tooling, and one sample stage. Both the wheel and the SDK archive carried the other platform’s launchers, and samples/data/ was a copy of the whole 31-file test-fixture directory when the launchers open exactly one stage. The sample READMEs still document both platforms, since the samples themselves are cross-platform.

  • The pinned ovstage runtime moved from 0.1.1.354763 to 0.2.0.372377. An environment that also pins ovstage directly has to move with it. The plugin set changed underneath – omni.usd gone, carb.tasking new – which the wheel and SDK hide, but a consumer assembling its own runtime tree by copying from the install layout should re-check what it copies. 0.2 also fixes an ovstage defect that returned instance-root paths absent from the stage.

Fixed#

  • The Linux wheel no longer ships three copies of the native library. A wheel is a zip and pip cannot restore symlinks, so the libovclash.so symlink chain packed three identical 4.4 MB members – 91% of the compressed wheel. It now stages the two names with consumers, the plain libovclash.so and the SONAME, and the CMake export is retargeted at the SONAME so find_package against an installed wheel keeps working. 6.05 MB down to roughly 4.22 MB. The SDK archive is unchanged.

  • Shell sample launchers ship executable. They arrived in the 0.1.4 wheels without the execute bit, so the documented run_*.sh invocation failed with Permission denied. The tracked mode is correct now and both the wheel build and the SDK install set it regardless, so the shipped mode no longer depends on the builder’s umask.

  • USD scene-graph instancing is expanded, so instanced geometry takes part in clash detection. An instanceable = true reference was invisible to a query: the backend reports one mesh per prototype in prototype space, so every real placement was absent and the prototype copy was collided at coordinates in no stage. Each prototype mesh is now replaced by one mesh per placement. Three defects went with it – nested placements collapsed onto their ancestor’s origin, any non-empty scope dropped all instanced geometry, and an invisible instance root still placed geometry. Instanced UsdGeomPoints no longer abort a run, though they still contribute no geometry.

  • A mesh excluded during Computing initial mesh data... is now named in the log. A Mesh whose triangulation is rejected is dropped from every later phase while nbMeshes keeps counting it, so the run returned zero overlaps, exit code 0 and an empty error – indistinguishable from a clean scene. With logging enabled the run now names each excluded prim and why. The exclusion itself and the default output are unchanged.

  • ClashRuntime.set_scope([], []) now clears the scope, as the C entry point has always documented; the Python wrapper skipped the native call when both lists were empty, so an earlier run’s scope stayed applied. Clearing is not the same as whole-stage traversal: an empty scope selects nothing until set_run_settings(enable_full_scene=True) turns the flag back on, and the header now states that three-state rule.

  • ovclash.AsyncPipeline.is_cancelled() keeps reporting a cancellation after cancel(). Cancelling has to finish the pipeline, which frees the cookie and clears the native flag, so is_cancelled() answered False for the rest of the object’s life – making a cancelled run indistinguishable from a clash-free scene. The flag is now latched while the cookie is live. The C ABI was correct and is unchanged.

  • Polling an async pipeline after cancelling or finishing it reports “not running” instead of raising. Both calls release the native cookie, but the polling methods still called into it, so the next poll raised – cancellation was unobservable through the call that exists to observe it. A terminated cookie now answers from the state the facade already tracks. Note the canonical ovclash package keeps the opposite contract: there the handle must not be used after finish().

  • save_as() to a .clashDetection target no longer retargets the open store. The legacy container is an export and the native layer deliberately leaves the store on the current .ovclashdb, but Python cached the export path anyway, so a later save() rewrote the container while get_file_path() reported the original file.

  • The exported ovclash::ovclash target’s -Wl,-rpath-link now names directories that can resolve something. It previously named only the package’s plugins directory, which holds no shared objects in the SDK and does not exist in the wheel, so the option could never resolve anything; that entry is removed. It now names the library directory, plus – for the wheel, where libovstage.so comes from the separate ovstage distribution – that distribution’s lib and bin. Set OVCLASH_OVSTAGE_LIBRARY_DIR to name it explicitly. Only existing directories are emitted.

  • A runtime that hands back an instance without a vtable reports a named error instead of faulting. The vendor wrappers dereference the vtable unguarded, so a runtime returning success with an unpopulated vtable faulted on the first open_stage() of a process, and the compatibility check meant to catch it read through one of those wrappers first. The vtable is now validated where instances are created. A diagnosability change: a process that was going to fail either way now says why.

  • The shipped C++ sample launchers honour OVCLASH_SAMPLE_BUILD_ROOT. The builders always compiled into that root but the launchers hard-coded their lookup, so redirecting it built the sample and then reported the executable missing – breaking the case the override exists for, since a wheel’s samples/ tree is usually not writable.

  • python -m ovclash leaves stdout to the JSON summary it promises. Bundled plugins narrated stage loading straight to file descriptor 1, landing ahead of the summary so the stream would not parse. They are native and never consult Python’s sys.stdout, so redirecting that could not have helped; descriptor 1 is now pointed at stderr for the run and the summary written to a reserved duplicate of the real stdout.

  • A Windows import failure now names the missing Visual C++ runtime. Windows packages deliberately do not bundle the MSVC runtime, but the failure surfaced as the raw loader text, which names a file that is present and suggests passing a full path that was already absolute. The runtime is probed rather than assumed, so a machine that cannot load the runtime DLLs is told exactly that, and one whose runtime is fine is told the missing dependency is something else. A genuinely missing file, and every failure on Linux, pass through untouched.

  • A stage path containing non-ASCII characters now opens on Windows. Paths crossing the C ABI are UTF-8, but the narrow std::filesystem and std::ifstream constructors decode with the ANSI code page, so a Cyrillic, CJK or accented path became a name that is not on disk and the existence check took the same branch as a genuinely missing file. Linux was unaffected, and unicode prim paths never were. The same defect silently emptied six text-USD fallbacks used for classification.

  • A rejected migration target no longer discards an extracted legacy store. migrate_data_structures_to_latest_version() migrates in place and never creates a missing file, so a not-yet-existing path is refused – but it was refused destructively: the cleanup that deletes the temporary store a legacy container is extracted into ran before the path was checked, so every later read came back empty. The path is now validated first, and both failure paths stopped discarding the reason, now reachable through a new last_error().

Documented#

  • The @return and @note Errors: clauses of every validating setter name the rejected-value case. The ten validating setters have always refused a bad value, stored nothing and recorded the reason, but only the @brief prose said so – and those two clauses are what IDE hovers and generated documentation show on their own, so a caller could conclude the value could not be refused. No behaviour changed.

  • The Suite settings-JSON documentation no longer claims non-object JSON is rejected. The validator has always accepted any syntactically valid JSON value, or the empty string, and that is unchanged; only the prose was wrong.

  • The Suite settings field catalogue no longer promises validation the backends do not perform. It grouped nb_tasks, tris_per_leaf, overlap_code and triangle_limit as counts with enforced maxima; only tris_per_leaf behaves that way. overlap_code is an unvalidated selector, triangle_limit treats 0 as unlimited, and nb_tasks is clamped to 256 rather than refused while reading back whatever was passed in.

  • max_local_depth_mode is documented as the mode selector it is, not a boolean. It picks one of three algorithms and is validated against [0,2]. Two things the old wording hid: compute_max_local_depth is the on/off gate, so with it clear every mode reports the “not computed” sentinel; and the scale is offset by one from ovclash_max_local_depth_mode_t, so a canonical enumerator passed here shifts the algorithm by a tier and HIGH is rejected outright.

  • The shipped agent skill states the real settings keys and API surface. Every settings example in ovclash-suite-python failed as written – SettingId members carry a SETTING_ prefix, and an unrecognised key is discarded in silence while set_settings() still returns True. Its API claims were also wrong: set_scope() takes literal prim paths rather than expressions resolved through a pxr stage, and several return shapes and type values were misdescribed. skills/ is packaged into the wheel, so these reach consumers the way the headers do, and they are written to be executed by an agent rather than read. SKILLS.md is corrected with them.

  • The shipped usd-core guidance no longer contradicts the wheel’s own metadata. SKILLS.md told consumers not to install usd-core at all while the same wheel declares it under the [viewer] extra, which the ovRTX sample needs. The warning now names the extra as the sanctioned exception and records that usd-core comes from public PyPI, so the extra needs --extra-index-url. Whether a second pxr can shadow the runtime ovclash loads is a separate question, not settled here.

Known issues#

  • A newline anywhere in the command line crashes the first open_stage() on Linux. An argument containing a newline – most easily a multi-line python -c body – kills the process with SIGSEGV, with no traceback. Windows is unaffected. The cause is upstream in Carbonite, which reads /proc/self/cmdline with std::getline and so truncates a NUL-separated blob. Workaround: keep newlines out of the argument vector; running the same source from a script file works.

[0.1.4] - Date 2026-08-11#

Changed#

  • Both Python APIs moved under the ovclash package, as ovclash.python.api (canonical C ABI) and ovclash.python.suite, so one package directory anchors the Python sources, the native payload and the C SDK. from ovclash import ClashRuntime and import ovclash_suite keep working: ovclash/__init__.py re-exports the public names and aliases the old submodule spellings in sys.modules, and a top-level ovclash_suite module aliases the relocated package rather than re-exporting from it, so from ovclash_suite._bindings import lib still resolves to the same module object.

Added#

  • The wheel now ships documentation and agent skills: docs/ (overview, C/C++ quickstart, changelog), SKILLS.md, and one skill per API surface – canonical and suite, each in Python and C.

Fixed#

  • The wheel’s zip entry timestamps are pinned via SOURCE_DATE_EPOCH, keyed to the commit that last touched VERSION. Previously every build stamped entries from file mtimes, so a fresh CI clone produced different bytes for identical source and a republish could never match an already published version. The native payload is not yet reproducible (the link carries a wall-clock timestamp, and signed builds cannot be), so this makes a job retry idempotent, not a pipeline re-run.

[0.1.3] - Date 2026-08-10#

Changed — breaking (C ABI)#

  • The canonical header moved to include/ovclash/ovclash.h. Include it as <ovclash/ovclash.h>; <ovclash.h> no longer exists and there is no compatibility shim. Nothing else about the header changed — same entry points, same types, same ABI.

    It now sits beside ovclash/ovclash_export.h and ovclash/version.h under one library-named directory, matching <ovclash_suite/*.h>, matching ovphysx (<ovphysx/ovphysx.h>), and matching the installed-tree layout the OV Libraries guidelines prescribe. The old split — a bare include/ovclash.h next to an include/ovclash/ directory — was a standing source of confusion. Shipping the primary header at the include root also risked colliding with any other SDK on the same include path.

    No deprecation cycle: the library has no external C consumers yet, so a shim would have preserved the confusion for nobody’s benefit.

  • ovclash_result_t is now a struct, typedef struct ovclash_result_t { ovclash_status_t status; }, matching ovclash_suite_result_t. It was a bare typedef ovclash_status_t ovclash_result_t. Test it as result.status == OVCLASH_STATUS_SUCCESS; in Python use ovclash._bindings.ok(). The struct owns no memory and is safe to copy by value.

    This exists so the return type can gain fields without changing 81 signatures again, and so a result cannot be silently used as an integer or a bool — which matters here because OVCLASH_STATUS_SUCCESS is 0.

  • Every canonical entry point now returns ovclash_result_t. Previously the ABI mixed 40 void returns, 4 bool, a uint32_t count and an ovclash_async_t*. Values that used to be returned directly now travel in out-parameters:

    before

    after

    uint32_t ovclash_create_pipeline(ctx)

    ovclash_result_t ovclash_create_pipeline(ctx, uint32_t* out_step_count)

    ovclash_async_t* ovclash_run_pipeline_async(ctx)

    ovclash_result_t ovclash_run_pipeline_async(ctx, ovclash_async_t** out_async)

    bool ovclash_is_pipeline_running(async)

    ovclash_result_t ovclash_is_pipeline_running(async, bool* out_running)

    ovclash_get_result_string, ovclash_get_last_error and ovclash_get_version_string still return ovclash_string_t directly: the first two are the error-reporting channel, so routing them through it would be circular, and the third takes no context and cannot fail.

    There are no compatibility aliases. Note that OVCLASH_STATUS_SUCCESS is 0, so a result must never be tested for truthiness — that is what the struct above exists to prevent. Compare result.status against OVCLASH_STATUS_SUCCESS; in Python use ovclash._bindings.ok().

  • ovclash_set_use_USDRT() is removed. The lowercase ovclash_set_use_usdrt() was previously a forwarding alias and is now the only spelling. The flag remains inert on both backends — it is stored, serialized and reported, and selects nothing.

Added#

  • ovclash.ClashRuntime.destroy() releases the native context and is now the primary spelling, so the two Python layers name the operation the way ovclash_suite’s main object already does. close() remains as an alias, because the context-manager protocol and existing callers use it. Both are idempotent.

  • ovclash_suite.ClashData publishes the legacy-container spellings as class constants: CLASH_DATA_LAYER_FILE_EXT (.clashDetection), CLASH_DATA_FILE_EXT (.clashdata), and the two customData keys written on such a container’s USD layer, CLASH_DATA_LAYER_CUSTOM_CLASH_DB_PATH (clashDbPath) and CLASH_DATA_LAYER_CUSTOM_MODIFIED (clashDbModified).

  • omni.physxclashdetectioncore.utils.get_available_system_memory(), which upstream answers from Kit’s omni.gpu_foundation_factory. There is no Kit here, so it asks the OS, and it keeps upstream’s “0 means unknown” return contract.

  • omni.physxclashdetectioncore.config.ExtensionConfig.extension_path, which upstream declares as Optional[str] = None and Kit sets at extension startup. There is no extension here, so it keeps Kit’s own default of None and code that reads it — or checks it for None — behaves the same against this package.

Fixed#

  • The wheel ships the public headers. ovclash/include/ was staged into the package but was missing from the wheel’s package-data list, so pip install ovclash delivered the ovclash/lib/cmake/ovclash package config pointing at an include directory that was not there.

  • The Windows sample wrappers accept options again. run_clash_api_cpp.bat --release — the spelling the sample READMEs document — aborted with '...\clash_api\--release' is not recognized as an internal or external command before either backend ran, and the same held for --debug, --config, --output-dir and --stage under the default --backend both. cmd.exe’s shift shifts %0 along with %1..%9, so the %~f0 used to re-launch the wrapper once per backend named the last consumed option, resolved against the caller’s current directory. The four run_clash_*_{cpp,python}.bat wrappers now capture %~f0 before parsing, as build_wheel.bat already did. The same slip made <wrapper> --release --help print Usage: --release; that is fixed in those four plus test_all.bat, build_samples.bat and both run_legacy_clash_detection_*.bat. Results are unchanged — only argument handling was wrong, and the Linux .sh wrappers were never affected, since POSIX shift leaves $0 alone.

  • A persisted transform matrix containing a subnormal value (for example 4.9406564584124654e-324) could not be read back on Linux, which made the whole clash_frame_info row unreadable. The reader treated strtod’s ERANGE as a parse failure, but whether ERANGE is raised for a result that merely underflows to a subnormal is implementation-defined and glibc and the UCRT disagree. Overflow is still rejected.

Documented#

No behaviour changed here; these entries state contracts that were previously left implicit.

  • The overlap-group index is an identifier, not a rank. ovclash_get_overlap_data now says that which group sits at which index is not part of the contract. Two runs over the same stage with the same settings report the same set of groups with the same data, but not necessarily in the same order, and the two backends do not agree on order with each other. Match groups by name0/name1 or clashHash, and sort in the consumer if a deterministic sequence matters.
